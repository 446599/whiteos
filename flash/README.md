# whiteos 网页烧录

入口：<https://446599.github.io/whiteos/flash/>。

支持 Web Serial 的电脑浏览器可选择“全新烧录”或“固件更新”。页面加载时识别在线版本，不自动连接设备；也可导入本地完整包。

## 默认在线烧录

进入页面会自动选择在线固件，顶部明确显示“在线固件 · 默认使用”、版本与来源。直接点击“固件更新”或“全新烧录”，网页自动下载并校验，无需先下载或导入文件。加载期间等待版本识别，不切换到本地来源。

本地导入位于状态区下方，默认折叠为“在线下载失败？使用本地完整包”。只有在线版本加载或下载失败时自动展开；也可主动展开。导入后顶部明确切换为“本地固件”，可点击“切回在线固件”恢复默认方式。

## 本地导入与下载（备用）

1. 打开 [GitHub Releases](https://github.com/446599/whiteos/releases)，展开目标版本的 **Assets**。
2. 下载 `whiteos-X.Y.Z-full.bin`。不要选 `whiteos.bin`、Source code；ZIP 需先解压。1.1.2 及更早已发布版本没有完整 BIN，可继续使用在线烧录。
3. 回烧录页，展开备用导入入口，点“选择完整包 .bin”。页面从镜像内部读取版本，并检查产品、芯片、三份镜像、分区布局及完整性；文件只在浏览器内存中处理。
4. 已有 whiteos 选“固件更新”；首次安装选“全新烧录”。完整包兼容两种方式，更新仍只写应用，不整体写入包里的填充间隙。

导入检查期间禁止烧录；失败会清空当前可烧录来源，不会悄悄使用之前的版本。可重新选择同一文件，或明确点击“切回在线固件”。在线结果晚到不会覆盖已导入文件。保留当前和历史正式版的更新说明，本地导入时隐藏不属于所选文件的在线说明。

## 固件源

正式发布包为 GitHub Release 附件，烧录所需文件包含：

- `manifest.json`
- `bootloader.bin`
- `partition-table.bin`
- `whiteos.bin`

`config.mjs` 中的 `firmwareSource` 已配置为：

```js
export const firmwareSource = {
  type: "release",
  owner: "446599",
  repo: "whiteos",
  indexPath: "../firmware/releases.json",
};
```

网页不直接跨域读取 Release 附件，也不请求匿名 GitHub API。部署工作流读取公开仓库正式 Release，核对附件与清单，再同步到 Pages 的 `firmware/releases/vX.Y.Z/`。`firmware/releases.json` 指向最高正式版本；一旦开始操作，清单和三份镜像锁定在同一版本目录。下载失败不会退回其他版本。旧正式版本目录也会保留在每次部署中。

发布、编辑或删除 Release，以及更新 main 或手动执行工作流，都会重新部署。草稿和预发布不会进入稳定烧录源。详细附件格式与步骤见 [Release 发布格式](../RELEASE_FORMAT.md)。原提交固定源读取逻辑仅保留作显式配置回滚，不作为自动降级。

固件清单格式：

```json
{
  "schema": 1,
  "board": "read-pico-4.7",
  "chip": "ESP32-S3",
  "flashSize": 16777216,
  "partitionTableOffset": 32768,
  "version": "实际发布版本号",
  "parts": [
    {
      "role": "bootloader",
      "offset": 0,
      "file": "bootloader.bin",
      "size": "实际字节数，必须为整数",
      "sha256": "实际文件的64位小写SHA-256"
    },
    {
      "role": "partitions",
      "offset": 32768,
      "file": "partition-table.bin",
      "size": "实际字节数，必须为整数",
      "sha256": "实际文件的64位小写SHA-256"
    },
    {
      "role": "application",
      "offset": 65536,
      "file": "whiteos.bin",
      "size": "实际字节数，必须为整数",
      "sha256": "实际文件的64位小写SHA-256"
    }
  ]
}
```

上面是字段说明，不是可用发布清单，不能直接用于烧录。镜像地址须来自实际 ESP-IDF 构建参数，大小与 SHA-256 必须由真实文件生成；不得填入示例值或将应用镜像写到 `0x0`。

## 安全边界

- 仅用于 ESP32-S3、16 MB Flash 的小纸 Pico，筛选原生 Espressif USB 串口。
- 下载镜像先核对大小、SHA-256、镜像头和发布包中的分区布局。连接后不读取或比对设备分区表，按发布清单直接写入。
- 全新烧录不等于恢复出厂设置，不整片擦除、不清空 NVS、不操作 TF 卡或 PMU。
- 全新烧录写入启动程序、发布分区表和应用；固件更新只写应用，适用于已安装 whiteos 的设备。页面不根据设备原有分区表阻止写入，也不执行数据迁移。
- 固定分区：NVS `0x9000 / 0x5000`、PHY `0xE000 / 0x1000`、factory `0x10000 / 0x800000`、storage `0x810000 / 0x500000`。
- 安全启动、Flash 加密或无法确认安全状态的设备停止操作。
- 写入后在设备内按最多 512 KB 一段计算 MD5，与已通过 SHA-256 校验的下载内容对比；保留写入扇区之外全部 Flash 的前后摘要检查，不进行整片备份或上传设备内容。
- 单次设备校验最多等待 15 秒，无响应停止并要求重新连接；保护区域及镜像检查均逐段更新进度。MD5 用于检查写入结果，下载完整性仍用 SHA-256。
- 全新烧录有写入前确认。烧录时不要断开 USB 或关闭页面；中断可能需要重新烧录。
- 下载、取消、写入或校验失败不会被当作安装成功。通过写入校验也不等于设备启动与屏幕功能已经验收。

1.0.0 的编译、内部版本、镜像与分区校验已通过；该构建尚未完成真机启动与屏幕验收。此网页不提供硬件身份认证，也不保证其他 ESP32-S3 设备兼容。

2026-10-09 实机网页测试：Edge 可复现原版在 25% 分区读取阶段停滞；命令响应后没有收到分区数据包，读取报 `No serial data received`。改用设备摘要后，同一设备的 4 KB 分区表检查约 11 ms 完成，随后完成 1.0.0 应用更新、镜像摘要与全部保护区域检查，页面显示 100% 并发送重启指令。全新烧录仍只完成自动化验证；本次未执行整片擦除、分区迁移、TF 或 PMU 操作。

2026-10-09 按用户要求取消设备分区表兼容性检查。仍保留芯片、容量、安全状态、下载完整性、写入内容及写入范围外的保护区域检查。
